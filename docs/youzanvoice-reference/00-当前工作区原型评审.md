# 当前工作区原型评审

> 快照日期：2026-07-29
> 范围：当前未提交工作区中的自动词典学习与屏幕上下文改动

本文件记录工作区当前原型的实际行为，并与本目录的目标设计建立对应关系。后续文档中的“目标”描述面向可发布版本；当前原型为功能验证提供基础，也暴露出隐私、会话边界和模型兼容性方面的加固项。

## 当前原型概览

| 能力 | 当前工作区实现 | 目标设计 | 优先级 |
| --- | --- | --- | --- |
| 本地词典候选 | `src/lib/correctionLearner.ts` 实现差分、LCS、中文局部替换、词条过滤和编辑距离判定。 | 候选携带置信度与理由编码，支持可审计的 `auto_local` 来源。 | P0 |
| 词条规范化 | `src/lib/termCanonicalizer.ts` 在粘贴前归一英文大小写、分隔符和近似拼写。 | 保留现有行为，补充可解释的命中记录与边界测试。 | P1 |
| 词典回退 | 本地无候选时，`useVoiceFlowStore.ts` 将原文和字段摘录发送给 `analyzeCorrections()`。 | 只把受限的边界候选交给可选 LLM 复核。 | P0 |
| 词条来源 | 本地与 LLM 结果都经 `addAiSuggestedTerm()` 写入 `source = 'ai'`。 | 本地学习使用 `auto_local`，LLM 复核使用 `ai_review`。 | P1 |
| 屏幕采集 | `screen_context.rs` 录音开始时截取主显示器 PNG，转成 Base64 后立即删除临时文件。 | 专用助手热键、窗口优先、`captureId` 租约、范围和权限控制。 | P0 |
| 图像请求 | `enhancer.ts` 将 Base64 和前台应用名附加到普通听写的文本整理请求。 | 上下文助手单独运行、结果预览、用户显式复制或插入。 | P0 |
| 模型能力 | `llmProvider.ts` 已支持 OpenAI-compatible `image_url` content part。 | 引入显式视觉能力配置和请求前预检。 | P1 |
| 临时资源 | PNG 文件在 Rust 中读取后立即删除；Base64 保留在前端会话变量。 | 统一会话清理、TTL、取消和应用启动清扫。 | P1 |

## 自动词典学习原型

### 已实现部分

`src/lib/correctionLearner.ts` 已对照有赞参考实现完成以下核心能力：

- 词级 LCS 对齐删除块与插入块。
- 中文局部替换定位及相邻字符辅助判断。
- 中英混合词、Latin 标识符与短词候选提取。
- 长度、词数、标点、句子碎片、代词、语气词和危险字符过滤。
- 英文候选的编辑距离判定，以及中文短词的字符编辑距离判定。
- 与现有词典的大小写无关去重。

`src/stores/useVoiceFlowStore.ts` 已在修正监控结果到达后优先调用 `extractCorrections()`，并在粘贴前调用 `canonicalizeTranscription()`。现有 `tests/unit/correction-learner.test.ts` 覆盖英文术语、中文局部修正、整句重写、重复词和规范化基础用例。

### 当前加固项

| 观察 | 风险 | 目标处理 |
| --- | --- | --- |
| 本地候选为空时自动执行全文 LLM 分析。 | 原粘贴文本与字段摘录可进入网络请求。 | 将 LLM 改为用户开启的边界候选复核，默认关闭。 |
| 本地候选与 LLM 候选都写入 `source = 'ai'`。 | 用户无法了解词条学习来源。 | 增加 `auto_local`、`ai_review` 以及学习审计事件。 |
| 修正日志含原文、字段摘录、候选列表和 LLM 原始回复。 | 日志可能包含聊天、代码和业务数据。 | 用长度、数量、耗时、策略和错误类别替换内容日志。 |
| 算法只导出 `extractCorrections()`。 | 置信度与筛选原因无法进入 UI、审计和 LLM 复核。 | 在后续重构中增加候选对象和纯函数测试导出。 |
| 当前测试集中于算法基线。 | 监听生命周期、写入来源、日志脱敏覆盖不足。 | 补充 `useVoiceFlowStore` 集成测试与日志检查。 |

完整目标见 [01-自动词典学习.md](./01-自动词典学习.md)。

## 屏幕上下文原型

### 当前数据流

```text
普通听写开始
  → capture_screen_context()
  → 截取主显示器 PNG
  → Rust 读取并 Base64 编码
  → 删除临时 PNG
  → Base64 与前台应用名保存在 pendingScreenContext
  → enhanceText() 构造 image_url data URI
  → 当前 LLM endpoint 执行普通听写整理
  → completePasteFlow() 自动粘贴整理结果
```

相关文件：

| 文件 | 当前职责 |
| --- | --- |
| `src-tauri/src/plugins/screen_context.rs` | 采集主显示器、读取 PNG、Base64 编码、删除临时文件。 |
| `src-tauri/src/lib.rs` | 注册 `capture_screen_context` 与 `cleanup_screen_context_temp`。 |
| `src/stores/useVoiceFlowStore.ts` | 听写开始时异步采集，文本整理时传入 `screenContext`。 |
| `src/lib/enhancer.ts` | 构造 OpenAI-compatible `image_url` content part。 |
| `src/lib/llmProvider.ts` | 将聊天消息 `content` 扩展为字符串或多模态 parts。 |
| `src/stores/useSettingsStore.ts` | 持久化 `screenContextEnabled` 开关。 |
| `src/views/SettingsView.vue` | 提供屏幕上下文开关及提示文案。 |

### 当前加固项

| 观察 | 风险 | 目标处理 |
| --- | --- | --- |
| 开关开启后，每次普通听写都会截取主显示器。 | 采集范围宽，语音听写与屏幕理解的用户意图混合。 | 使用专用上下文助手热键和可见的范围标签。 |
| `screen_context.rs` 采集主显示器。 | 焦点窗口之外的聊天、密码管理器、机密看板可能进入截图。 | AX / 窗口边界优先，显示器作为明确标记的回退路径。 |
| Rust 将 PNG Base64 返回给 WebView。 | 图像在前端内存和网络 payload 中占用较大，也扩大访问面。 | WebView 只处理 `captureId`；Rust 管理图片租约与视觉请求。 |
| 当前实现没有截图尺寸、字节数、采集超时和并发限制。 | 大屏、高 DPI 和多次触发可能造成内存与网络压力。 | 设置图像上限、缩放、超时、单会话 guard 与 TTL。 |
| 模型只依据用户填写的 model ID 接收图片。 | 文本模型可能拒绝多模态消息。 | 增加视觉能力配置、预检和可识别错误。 |
| 前台应用名直接进入 LLM 请求和日志。 | 应用标识可能具有隐私含义。 | 本地分类为通用场景标签，日志只记录受控类别。 |
| 普通听写结束后自动粘贴增强结果。 | 屏幕推理结果缺少用户预览与确认环节。 | 上下文助手独立结果卡，插入操作由用户显式触发。 |
| 当前提示把截图作为增强线索。 | 截图中的网页、代码、终端文本可能包含提示注入。 | 视觉系统提示将屏幕内容定义为非可信材料。 |

完整目标见 [02-截图上下文助手.md](./02-截图上下文助手.md) 和 [03-上下文与数据边界.md](./03-上下文与数据边界.md)。

## 建议的合入顺序

1. 先保留本地词典学习原型，完成来源标记、日志脱敏和 Store 集成测试。
2. 将 LLM 全文回退改为设置控制的结构化候选复核。
3. 将屏幕上下文原型隔离为专用上下文助手模式，完成 Pencil 设计、权限流程和结果预览。
4. 用 `captureId` 与 Rust 临时租约替换前端 Base64 图像传递。
5. 完成 ASR 上下文合约测试、视觉模型能力验证和 macOS 真机验收后再发布。

实施顺序、迁移和测试门见 [04-实施顺序与验证.md](./04-实施顺序与验证.md)。
