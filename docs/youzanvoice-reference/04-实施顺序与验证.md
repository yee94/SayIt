# 实施顺序与验证

## 交付策略

自动词典学习和截图助手都接触粘贴、输入框读取、音频、截图、模型请求、SQLite 与 HUD。交付采用由低风险到高风险的顺序，让每一阶段都保留独立可验证的用户价值。

```text
Phase 0 设计与基线
  → Phase 1 本地自动词典学习
  → Phase 2 可选 LLM 复核与 ASR 上下文
  → Phase 3 macOS 截图上下文助手
  → Phase 4 Windows 与跨模型完善
```

## Phase 0：数据流与基线

### 目标

冻结用户可见行为、数据边界和验证夹具，为后续实现提供共同契约。

### 产出

- 将当前工作区原型与 [00-当前工作区原型评审.md](./00-当前工作区原型评审.md) 的发布前加固项逐条确认。
- 一组词典学习的纯函数 fixtures：英文术语、中文短词、混合脚本、整句改写、无关字段、已有词。
- 一组截图助手的 mock capture 与 vision response fixtures。
- 与真实豆包账户进行 `corpus.context` 组合格式验证。
- 性能基线：当前听写从热键到粘贴的 P50 / P95，用于防止后台学习引入回归。

### 通过条件

1. 设计稿列出所有新增控制与错误状态。
2. 数据流完成 [03-上下文与数据边界.md](./03-上下文与数据边界.md) 的实施前检查清单。
3. 现有自动词典学习、录音、粘贴和历史测试全绿。

### 实现规则

- 复用 `completePasteFlow()` 之后的 fire-and-forget 位置。
- 复用 `start_correction_monitor`、`CORRECTION_MONITOR_RESULT`、`read_focused_text_field` 和 `VOCABULARY_LEARNED`。
- 保持当前 500ms 快照轮询与 15 秒修正监控硬上限。
- 高置信度候选本地写入，低置信度候选本次结束。
- 诊断日志只记录长度、候选数量、策略、耗时和错误类别。

### 通过条件

1. 词典候选纯函数测试覆盖 [01-自动词典学习.md](./01-自动词典学习.md) 的全部表格用例。
2. 已有词条只增加权重；重复词不会产生第二条 SQLite 记录。
3. 全句重写、无关字段、URL、路径和密码样式文本不产生词条。
4. 词典学习异常不影响粘贴成功状态和下一次录音。
5. 前端、Rust 和 Sentry 日志中不存在原文本与字段摘录。

| `tests/unit/asr-context.test.ts` | 覆盖 JSON、上限、截断和降级。 |

### 合约门

- LLM 复核仅在用户开启时执行，并将 API 用量记录为 `vocabulary_analysis`。
- ASR 上下文只在真实豆包账户验证 JSON 格式后启用。
- ASR 请求错误时，自动重试一次仅含热词的上下文；重试次数严格限制为一次。
- 近期转录默认关闭，清除动作立即清空内存缓存。

### 通过条件

1. LLM 复核请求中没有完整字段摘录。
2. `corpus.context` 是合法 JSON 字符串，现有热词注入保持工作。
3. 上下文超出预算时保持最新、最相关条目，且请求仍能完成。
4. 关闭任一开关后，网络请求立即移除对应上下文。

### SQLite v9 设计

v9 保持单一、幂等的迁移入口：

```sql
CREATE TABLE IF NOT EXISTS vocabulary_learning_events (
  id TEXT PRIMARY KEY,
  vocabulary_id TEXT,
  source TEXT NOT NULL CHECK(source IN ('auto_local', 'ai_review')),
  confidence TEXT NOT NULL CHECK(confidence IN ('high', 'review')),
  reason_list_json TEXT NOT NULL,
  original_length INTEGER NOT NULL,
  field_excerpt_length INTEGER NOT NULL,
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  FOREIGN KEY (vocabulary_id) REFERENCES vocabulary(id)
);

CREATE TABLE IF NOT EXISTS context_assistant_runs (
  id TEXT PRIMARY KEY,
  transcription_id TEXT,
  capture_mode TEXT NOT NULL CHECK(capture_mode IN ('window', 'display')),
  model TEXT NOT NULL,
  result_char_count INTEGER NOT NULL,
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  FOREIGN KEY (transcription_id) REFERENCES transcriptions(id)
);
```

`api_usage` 的 CHECK 值加入 `context_assistant` 时，沿用 v3 的重建与恢复策略：检测 `api_usage_new`、优先恢复可用副本、复制数据、原子替换逻辑改为幂等步骤。旧 migration 保持原样。

### 通过条件

1. 用户按下专用热键后，系统在 HUD 改变焦点前记录目标范围。
2. 屏幕录制权限、辅助功能权限、排除应用、安全字段和模型能力分别提供可识别的错误状态。
3. PNG 通过 `captureId` 管理，WebView、SQLite 和日志没有绝对路径。
4. 成功、失败、Esc、超时与应用重启后，临时 PNG 均被清除。
5. 用户点击“插入结果”前，助手永远不调用 `paste_text`。
6. 使用包含恶意文字的网页截图时，模型输出仍遵守用户语音指令和系统提示。

## Phase 4：Windows 与跨模型完善

### 目标

- 完成 Windows 前台窗口、截图、DPI、多显示器、最小化窗口和受保护内容的实现。
- 统一 OpenAI-compatible 视觉请求与具有不同图像协议的 provider 适配器。
- 将模型能力配置从单个布尔值扩展为明确的能力描述。
- 根据用户反馈调整上下文上限、截图压缩和助手结果交互。

### 通过条件

1. Windows 手动与自动化测试覆盖窗口截图、显示器回退和权限/受保护内容错误。
2. 各 provider 适配器都有请求序列化和响应解析单元测试。
3. 不支持视觉的模型在 UI 中显示为不可选，且底层 command 返回可识别错误。

## 验证矩阵

| 层级 | 验证 | 命令或方法 |
| --- | --- | --- |
| TypeScript 纯函数 | 差分、过滤、上下文截断、模型 payload | `pnpm test -- tests/unit/correction-learner.test.ts` |
| Store 集成 | 监听生命周期、词典写入、HUD 通知、session guard | `pnpm test -- tests/unit/use-voice-flow-store.test.ts` |
| Rust 单元测试 | JSON 上下文、租约、范围选择、清理计划 | `cargo test --manifest-path src-tauri/Cargo.toml` |
| 前端静态检查 | 类型与 Vite 构建 | `pnpm build` |
| 数据库升级 | v8 fixture 升级至 v9、重复执行、故障恢复 | 专用 migration fixture + Vitest / 手动 SQLite 检查 |
| macOS 手动测试 | 权限、窗口截图、显示器回退、Esc、异常退出 | 真机验收清单 |
| E2E | 结果卡、复制、显式插入、设置开关 | `pnpm test:e2e`（具备可控 mock 时） |

文档本身使用以下校验：

```bash
node scripts/check-simplified-chinese.mjs
node scripts/validate-repo-hygiene.mjs
```

## 发布门

每个 Phase 合入前满足：

- [ ] 只修改当前阶段列出的功能范围和必要的共享契约。
- [ ] 现有用户改动已保留，未被无关重排覆盖。
- [ ] 新增设置有默认值、迁移逻辑和 i18n。
- [ ] 新增 Tauri command 已注册、类型化、测试并具备错误分类。
- [ ] SQLite 迁移为新版本，历史 migration 保持不变。
- [ ] 诊断日志通过敏感数据审查。
- [ ] 所有针对本阶段的测试、构建与人工验收记录完成。

实现从 Phase 0 的 ASR 合约测试开始，再进入 Phase 1 的纯函数词典学习。
